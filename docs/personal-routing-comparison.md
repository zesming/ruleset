# 个人分流与 DNS 对照

本记录使用同一份归档输入，分别展开原配置和迁移配置的完整业务规则顺序。它验证重构产生的变化，不把上游更新或旧客户端缓存差异算作重构结果。完整配置、节点信息和原始对照报告仅保存在本地私有工作目录。

## 行为

| 业务 | 原配置 | 迁移后 | DNS 归属 |
|---|---|---|---|
| 未命中、未列出的日本域名 | 默认代理选择器，Surge 可在美日间变化 | US | US |
| 已复核的 JP 业务 | 无独立集合 | 保留空 JP 路由与 DNS 接口 | 当前无 JP 成员 |
| LAN、公司域名 | 直连，使用本地例外 | 保留 | 系统解析器 |
| AT&T ePDG | US、真实 IP | 保留 | US |
| AI、Apple Intelligence | AI 代理策略 | US，仍优先于通用直连 | US |
| AI 的微软附件与 Bing 域名 | AI 规则优先 | 保留 | US |
| 普通 Apple、Microsoft | 默认直连，可在旧选择器手动调整 | DIRECT | 国内解析器 |
| Nintendo 与其他游戏下载 | 直连下载 | 保留 | 国内解析器 |
| CDN 与国内规则重叠，例如 `bmp.ovh` | CDN 代理优先 | US | US |
| 测速、出口查询 | TEST 选择器 | TEST，默认 US | US |
| 本地测速网站、面板例外 | 显式直连优先 | 保留 | 保留原解析器 |
| 拦截 | REJECT 及平台变体 | 保留 DROP／NO-DROP 差异 | 保留原 US 解析策略 |

JP 不使用 `.jp`、日本 GeoIP 或全平台 Nintendo 规则自动归类。后续只添加有明确日本出口需求且有来源、理由的成员。Nintendo STUN 子域增加真实 IP 兼容例外，不因此改走 JP。

业务分类包含域名、关键词、通配符、进程、IP 和平台条件。DNS 选择器只提取域名条件，保留海外例外在国内集合之前的顺序。Surge 的内部 DNS 选择与代理服务器远端解析是两个阶段；这里的“DNS 归属”指本地配置选择的解析器和发送出口，不证明远端代理的全部解析过程。

## 验证结果

| 项目 | Mihomo | Surge |
|---|---:|---:|
| 路由代表值探测 | 1,353,090 | 1,353,112 |
| 域名 DNS 代表值探测 | 1,351,178 | 1,351,178 |
| 独立验收用例 | 21 通过 | 21 通过 |
| DNS 归属差异 | 0 | 0 |
| 业务路由差异 | 0 | 旧代理选择器收敛为 US |

代表值包含旧／新规则的重复探测、派生子域和显式元数据，不是独立域名数，也不是实际流量覆盖率。无法构造代表值的规则、URL 可见性、SNI／HTTP Host、DNS 解析状态等均在私有报告中单列。

旧配置的策略组按已声明的第一选择递归展开，TEST 保留逻辑选择器身份；这不等于客户端记忆的手动选择或实时 Smart 结果。Surge 的 11,844 个代表值从该静态 JP 选择变为 US，是默认出口收敛的设计变化，不能解释成对应比例的实际流量。现行 Surge CLI 的独立检查确认普通 Apple 仍为 DIRECT、拦截规则仍为 REJECT，AI、CDN 与 TEST 优先级符合对照预期。

实际 Mihomo 内核已加载完整规则集合，JP 为零成员；9 个路由抽查通过。另用独立的本地解析器替换生产 DoH 端点，在保留真实规则及顺序的条件下完成 11 个 DNS 选择抽查：AI、Apple Intelligence、微软附件、AT&T、CDN／国内重叠、普通国内服务、LAN 与默认 US 均符合预期。该检查使用 redir-host 暴露解析器返回值，验证选择顺序，不验证生产 DoH 传输、fake-IP 分配或手机接管设置。

两份完整候选分别通过 Mihomo 与 Surge CLI 校验。JP 的 Mihomo TUIC 节点使用独立的身份与基础协议参数，实际请求返回 HTTP 200，出口检查为 JP；现行 Surge JP TUIC 的 CLI 探测返回 HTTP 204。该单次连通性证据不代表高峰期线路质量或游戏表现。

Surge 的进程集合与会触发解析的 LAN IP 集合保留两条顶层规则边界；不对整个 LAN 集合增加 `no-resolve`。这避免把“匹配结果相同”扩大成未经证明的 DNS 触发时序相同。Mihomo 按子规则匹配，保留其对应顺序。

## 部署边界

公开接入片段不含节点。完整候选需分别通过 Mihomo 与 Surge CLI 校验，首次切换还需确认引用的整版远端资源已发布，保存原文件并校验未被其他设备修改。PR 合并前不将现用配置指向尚不存在的 `main` 资源。

多个 `main` URL 分别更新仍可能短暂混版；一次 Git 提交保证服务端整版发布，不保证每个客户端同时刷新。新接口、格式或绑定变化由发布门禁阻止自动迁移。手机端、OpenClash 覆写、Switch 实际联机与 NAT 类型需要对应设备的运行证据，桌面检查不能代替。
